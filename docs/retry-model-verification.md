# 재시도 모델의 요청 단위 적용 검증

## 범위

- 관련 이슈: #195.
- 기준 소스: `f53797251940ff6ddbc0d0eff657a1779664aa51`.
- 기존 수동 모드에서 메시지의 `model`이 세션 기본 모델에 저장되던 문제를 수정함.
- 요청의 명시적 모델 선택은 해당 요청에만 적용함. 영구 모델 변경은 기존 세션 생성 및 `PATCH /sessions/{id}`로 유지함.
- UI 코드, 모델 허용 목록, Privacy 판단, 비용 경로, 모델 선택 우선순위는 변경하지 않음.

## 원인과 변경

- 기존 조건은 Auto 모드의 명시적 모델만 저장에서 제외하고, 수동 모드에서는 재시도 모델도 기본값으로 기록했음.
- `payload.model is None`인 기존 일반 전송만 선택된 기본 모델을 기록하도록 조건을 좁힘.
- 폐기된 모델의 대체 모델은 저장하지 않는 기존 조건을 유지함.
- 보고서/슬라이드의 일반 전송도 `model`을 보낼 수 있으므로, 이 값만으로 영구 설정 변경을 추정하지 않음. 빈 Agent 상속값과 초기 빈 모델값은 명시적 요청 모델 때문에 고정되지 않음.

## 검증

`tests/test_retry_model_persistence.py`는 ASGI HTTP 요청, 실제 라우터, 메모리 내 SQLite의 commit과 별도 ORM 세션 재조회를 사용함. 인증, 모델 카탈로그, 작업 공간 문맥, 모델 runner는 합성 fixture임. 모델 생성·외부 API·운영 DB를 호출하지 않음.

- 최초 29개 회귀: 수정 전 13개 실패/16개 통과, 수정 후 29개 통과함.
- 재시도 모델은 정확히 선택되지만 GET/DB 기본값과 다음 요청 모델까지 바뀌는 경로를 수정 전 확인함.
- 추가 대조군을 포함한 최종 집중 검사: 38개 통과함.
- 전체 API: 2,448개 통과, 1개 기존 skip, 경고 11개임.
- 전체 API Ruff 및 `git diff --check` 통과함.

38개 검사의 범위:

- 채팅/보고서/슬라이드의 저장 모델, Agent 상속, 초기 빈 모델에서 재시도 후 GET·DB 재조회·다음 요청을 확인함.
- Auto 비용절약 및 품질우선의 저장 모델 설정을 유지함.
- 세션 생성 시 지정 모델과 명시적 PATCH의 영구 변경을 유지함.
- 모델을 생략한 최초 일반 전송의 기본값 저장을 유지함.
- 보고서/슬라이드의 명시적 모델과 빈 모델 payload가 세션 설정을 덮지 않음을 확인함.
- 미허용 모델 403 및 없는 모델 400에서 저장 모델·메시지 행·실패 상태를 유지하고 runner를 실행하지 않음을 확인함.

## 근거 구분

- 앞선 통합 소스 `2633d4f7d0776a4dbf52a6592fa1bd24e6e34c07`의 production UI/mock API 12개는 클라이언트 payload 우선순위와 PATCH 부재만 확인한 결과임. 해당 mock은 실제 서버의 저장 부작용을 재현하지 않았으므로 이 수정의 영속성 증거로 사용하지 않음.
- 이 문서의 영속성 근거는 이번 SQLite/라우터 검사임. PostgreSQL 배포나 실제 모델 품질 검증을 의미하지 않음.
- 전체 테스트에서 유지된 기존 skip을 해결하거나 다른 기능/보안 문제가 모두 없다고 판단하지 않음.
